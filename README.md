# LinkedIn Approval Dashboard

Existing LinkedIn content workflow plus an automated **Gmail → Claude → Draft** pipeline for DeCircle Solar.

## What it does

Team members email content (a LinkedIn URL, exact post text, or both) to
`linkedin-post-bot@decirclesolar.com`. The app:

1. Polls that mailbox on a timer (or on demand).
2. Rewrites the content with Claude into a DeCircle Solar LinkedIn post (no publishing).
3. Adds it to the existing approval queue as a `pending` draft.
4. A human approves/rejects in the dashboard; approval publishes to LinkedIn automatically.

Claude never publishes directly — human approval is always required.

## Setup

1. `npm install`
2. Copy `.env.example` values into `.env` and fill in:
   - `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`
   - `ANTHROPIC_API_KEY`, `CLAUDE_MODEL`
   - `GMAIL_REDIRECT_URI=http://localhost:5000/gmail/callback`
   - `LINKEDIN_TOKEN`, `LINKEDIN_AUTHOR_URN` (existing)
   - `APIFY_TOKEN`, `LINKEDIN_PROFILE_URL`, `GEMINI_API_KEY` (weekly newsletter)
3. In Google Cloud Console, on the same OAuth client, add the Gmail redirect URI
   (`http://localhost:5000/gmail/callback`) to the authorized redirect URIs, and
   ensure the **Gmail API** is enabled for the project.
4. Start the server (`npm start`), open `http://localhost:5000/gmail/login`, approve
   the `gmail.readonly` prompt, then copy the printed `GOOGLE_GMAIL_REFRESH_TOKEN`
   into `.env` and restart.

Gmail uses the **minimal** `gmail.readonly` scope. Processed messages are tracked
locally in `data/processed-emails.json` (gitignored), so emails stay unread in Gmail
and are never processed twice.

## Processing triggers

- **Automatic:** `GMAIL_ENABLED=true` (default) runs an in-process timer every
  `GMAIL_POLL_INTERVAL_MS` ms (default 3,600,000 = hourly). Checking Gmail costs no
  tokens; Claude is only called when there is actually a new email.
- **Manual web:** `GET /check-gmail` on the dashboard server.
- **Manual CLI:** `npm run gmail:check` (one run, `node src/gmail/processor.js --once`).

## Token costs

One Claude call per email (prompt + brand guide + email body → post). No web search,
no topic picking, no extra calls for email drafts. Idempotency ledger prevents
re-processing/re-billing.

## Images for email drafts

On approval, email drafts get an image chosen by `EMAIL_POST_IMAGE_MODE`:
- `sharp` (default) — `assets/base.png` + headline overlay. **Zero tokens.**
- `gemini` — full infographic generated by Gemini (Google AI Studio); uses Claude for the infographic text and your `GEMINI_API_KEY` for the image.
- `none` — text-only LinkedIn post.

Set `GEMINI_API_KEY` in `.env` (get one at https://aistudio.google.com/apikey). The
model is configurable via `GEMINI_IMAGE_MODEL` (default `gemini-3.1-flash-lite-preview`). If Gemini
fails, the app falls back to `sharp`.
> Note: text models such as `gemini-3.1-flash-lite-preview` and `gemini-3.8-flash`
> return `NO_IMAGE`, and the dedicated image models (`gemini-3-pro-image`,
> `gemini-3.1-flash-image`) need a billed key — on a free-tier key, `gemini` mode
> always falls back to `sharp`. Use `EMAIL_POST_IMAGE_MODE=none` to skip image
> generation entirely (manual upload still works).

## Weekly LinkedIn newsletter digest

The **Newsletter** tab summarizes your own recent LinkedIn posts into one digest
post. A digest is generated once and kept — the tab just displays it, so
reloading the page costs nothing. Click **Rewrite newsletter** to scrape and
summarize again, or let the weekly timer do it (default Monday 09:00, local).

It never publishes by itself — the digest is queued as a `pending` draft on the
dashboard. Approve it like any other post, and it publishes **text-only** (no
image).

- **Scrape:** an Apify actor (`APIFY_ACTOR_ID`, default
  `harvestapi/linkedin-profile-posts`) reads your public profile. Requires
  `APIFY_TOKEN` and `LINKEDIN_PROFILE_URL`. Returned posts are filtered to the
  `NEWSLETTER_LOOKBACK_DAYS` (default 6) window and to posts authored by your
  own handle.
- **Write:** Gemini (`NEWSLETTER_MODEL`, default `gemini-3.1-flash-lite-preview`) writes the
  digest from `prompts/newsletter-prompt.txt`, within LinkedIn's 2,800-char limit.
- **Links:** each post's URL is shortened (`URL_SHORTENER`, default `is.gd,tinyurl`)
  so the digest shows a short "Read more:" link instead of the long URL. Set
  `URL_SHORTENER=none` to keep LinkedIn's canonical permalink. If every
  shortener fails, the permalink is used so a link is never broken.
- **Manually:** the **Rewrite newsletter** button on the Newsletter tab, or the
  **Generate newsletter digest** button on the dashboard (both `POST
  /newsletter/generate-digest`).
- **Automatically:** `NEWSLETTER_ENABLED=true` (default) at
  `NEWSLETTER_DAY`/`NEWSLETTER_HOUR`. Runs are mutually exclusive with the buttons.
- **Rewrite:** generating a new digest removes previous *pending* newsletter
  drafts; already-published newsletters are kept as history.
- The tab lists the posts the digest was built from (date, engagement, link).

No Google Sheet is involved. Costs: one Apify run per generation (paid per post
scraped) plus one Gemini call.

## Tests

```
npm test
```

Uses Node's built-in test runner (`node:test`) with mocked Gmail, Anthropic,
Gemini and Apify calls — no real API calls are made during tests.
